# Pass 6 route visibility, set A: cat, swallow, cosmos, gremlin, eagle

2026-10-07. Five islands from the twelve-island tally in RUN.md. Every fix lives in the island's pieces module so `tools/loops/rebuild.mjs` reproduces it; the helpers sit in `3d/pieces/sightline.js` (`camera`, `faceClimb`, `dropFront`, `moveFront`, `clearFloor`, `moveElevator`, `routeCells`, `courtCell`). `faceClimb` is wizard's `faceRamps` approach with three changes: it skips cells that hold a thing, it lowers the diagonal front of a landing cell before the orthogonal ones, and its budget is a parameter so the layout loop keeps a cell. Nothing in `3d/pieces/wizard.js` changed.

One shared tool changed: `tools/loops/layout-loop.mjs` no longer proposes a `ramp+` move whose ramp descends away from the camera (west or north at the default yaw). The first swallow rerun showed why: the loop put a west-descending ramp at 6,7 straight back onto the route one round after `faceClimb` removed the one at 5,7, because a shorter route lowers its cost and it had no camera test. The filter uses the same facing rule as `qa-visibility`.

Every number below is from `node tools/qa-visibility.mjs http://localhost:8765 <level>` at 900x800, `node tools/loops/pass.mjs <level>` (greedy = the walk tool's greedy policy, the figure of merit the brief capped at +25%), `qa-levels` (inside the pass), `qa-things`, and `qa-ride-keys` with an `--order` that hops into and out of the island. Profiles `.pp-profile-visa*`. Diagnosis shots came from a scratch copy of the visibility tool that renders a named floor test and lists every cell the landing search touched; the copy is not in the repo.
